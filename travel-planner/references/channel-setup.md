# 首次使用渠道：检查、引导、验证、回到原任务

高德和FlyAI默认直接按 [托管查询服务](hosted-service.md) 调用 service.py，首次自动领取体验凭证、后续自动续领。不要要求用户检查或安装FlyAI、申请高德/FlyAI Key、登录FlyAI控制台或找维护者领凭证。只有托管服务实际受阻并且用户选择自有账户接力时，才执行下方独立配置步骤；不要仅因本机没Key而触发配置。

这不是用户进入Skill后必须完成的安装问卷。三类入口都在首次需要某个渠道时执行：链接入口可能立即需要浏览器；已有行程先整理用户材料；探索入口可先了解约束。首次确实需要查票/酒店/门票时优先检查托管接口是否支持所需查询，具体餐厅区域确定后才检查点评登录。

## 先检查，再提醒

复用当前环境已可用的连接。分别记录工具存在、浏览器连接、站点登录、Key配置、实际查询结果；这些状态不能互相替代。检查只记录布尔状态、版本、核验时间、待完成步骤和待恢复任务，不保存Key、Cookie、登录截图或订单号，不导出到分享页面。跨会话先轻量核验，不凭上次成功宣称当前在线。

| 检查发现 | Agent行动 | 何时让用户操作 |
|---|---|---|
| 能力已可用 | 直接查询任务所需资料 | 不重复安装或登录 |
| 只有Skill，没有CLI/运行环境 | 检查官方安装说明与当前帮助，补实际缺的依赖 | 需要用户执行安装器/系统交互时给具体一步 |
| CLI存在，浏览器连接失败 | 查doctor、目标Chrome个人资料与扩展启用状态 | 需要安装/启用扩展时打开准确入口 |
| 浏览器连通，网站未登录 | 打开对应官方页面 | 用户自行扫码，完成后核验一次 |
| FlyAI可运行但缺Key/权限不足 | 说明影响哪项结果，打开官方控制台入口 | 用户自行登录、获取Key并在本机输入 |
| 用户暂时无法配置 | 保留待恢复任务，继续处理现有材料或可用渠道 | 不反复催促，不虚构已查数据 |
| 风控/验证码/频次限制 | 执行browser-research.md停机规则 | 不当成普通未登录循环引导 |

提醒必须说清：现在要查什么、检查发现缺什么、用户当前只需做哪一步、完成后如何继续。不一口气抛多页命令。用户说完成后验证该步骤，不把“安装成功”写成“采集成功”。普通修复沿用已有授权，不重复问确认；遇工具明确要求的权限再解释具体原因。

## OpenCLI / Chrome / 网站登录

入口（操作前核对官方当前说明）：
- 官方安装与诊断：https://github.com/jackwener/opencli
- Chrome官方商店：https://chromewebstore.google.com/detail/opencli/ildkmabpimmkaediidaifkhjpohdnifk
- 手动安装扩展包：https://github.com/jackwener/opencli/releases
- 本地扩展管理：`chrome://extensions`（这是浏览器内部地址，不是下载网址）。


1. 先检查已安装命令、版本与实际帮助，再用doctor确认连接。可用时沿用现有浏览器；不要为了安装而重启、退出用户账号。
2. 缺工具时按官方当前说明安装适合当前环境的CLI或桌面运行环境；不是装了OpenCLI Skill就一定有可执行程序。
3. 浏览器桥接方式需要Browser Bridge扩展。优先官方商店入口；手动安装才引导到chrome://extensions，启用开发者模式，选择实际含manifest.json的扩展目录，不能选整个源码仓库。
4. 检查扩展启用且连接到目标Chrome个人资料。多个人资料时核对用户已登录的那个，不以“看到Chrome窗口”代表选对了会话。多profile参数按本机帮助使用，旧版不支持就不要猜命令。
5. 连接成功后，仅在需要的平台登录。小红书已登录不代表点评已登录；普通登录由用户自行扫码。Agent可以协助打开入口，不能索要密码/Cookie。
6. 执行当前任务需要的少量查询，并遵守research_gate；真实结果才证明该渠道可用。已有其他可用浏览器能力时不强制用户为了读取一个链接安装OpenCLI。

提示示例：“接下来要读你发的小红书收藏。OpenCLI已经安装，但还没连上你常用的Chrome；请先启用这个浏览器里的OpenCLI扩展。连上后我会回到刚才那篇收藏继续读取。”示例中的状态必须来自实际检查。

## FlyAI自有账户备选（仅用户选择接力时）

1. 先检查当前Agent是否已有FlyAI能力/官方Skill或可读操作说明、CLI与所需Node环境。已可调用就跳过安装。需要时引导安装官方FlyAI Skill及运行依赖，不盲目重装，也不要求所有用户额外全局安装Skill。
2. 官方Skill来源：https://github.com/alibaba-flyai/flyai-skill/tree/main/skills/flyai 。先读当前SKILL.md及具体命令参考；按目标Agent支持的安装机制安装。CLI帮助验证成功只证明能运行。
3. 检查本地是否已有Key，只判断存在与否，不打印配置。没有Key时官方支持体验查询，但结果不够支撑所需报价/权限时，应及时引导配置；有Key仍需看实际响应，不能保证一定有精确报价。
4. 打开 https://open.fly.ai/ ，请用户自行登录并按当前页面获取API Key。按钮与获取资格以实际页面为准，不能编造控制台步骤，也不擅自购买额度。FlyAI开发平台登录、飞猪消费端登录和API授权不是同一状态。
5. 配置位置为当前电脑用户目录 `~/.flyai/config.json` 的 `FLYAI_API_KEY` 字段，同一用户换项目可复用，不写死维护者的用户名路径。用户在本机终端运行 `python3 <skill目录>/scripts/configure_flyai.py`，隐藏输入Key。Agent可打开终端和准备命令，但不让用户粘贴Key到聊天、命令参数或可分享文件。配置写入本机私有FlyAI配置。
6. 配置完成，执行一条当前行程需要的只读查询。区分认证失败、权限不足、无结果、掩码价格、日期不符；不要将所有失败都归因于“请重新登录”。核验成功后继续保存的酒店/车票/门票任务。

仅用户已选择自有账户后才可使用以下提示：“现在要比较你这两晚的酒店价格。当前只有体验结果，价格有掩码；需要你登录FlyAI官方平台获取Key，再在本机终端输入。配置好后我会继续查询这两个日期，不需要重新描述行程。”若用户已有可用Key，不发送此提醒。

## 高德：先检查可用MCP，再选API方式

需要准确地点或逐段路线时触发；不因高德缺Key跳过小红书、点评和FlyAI。

1. 先检查当前Agent可调用工具中是否已有高德MCP。已能成功查询就复用，不要求用户额外建立`.amap/config.json`。没有该文件不能据此断言没有MCP授权。
2. 缺少连接时，打开官方Key教程：https://lbs.amap.com/api/mcp-server/create-project-and-key 。引导用户登录高德开放平台控制台，在“应用管理”创建应用，添加Key，服务平台选择“Web服务”。以当前实际页面为准，用户自行完成账号登录。
3. MCP官方接入：https://lbs.amap.com/api/mcp-server/gettingstarted 。支持远程Streamable HTTP（官方推荐）和本地Node.js两种方式。远程地址形如 `https://mcp.amap.com/mcp?key=<用户自己的Key>`；本地官方包为 `@amap/amap-maps-mcp-server`，其环境变量为`AMAP_MAPS_API_KEY`。按当前Agent的配置方式设置，不直接套用其他客户端配置文件；不把真实带Key的地址发进聊天或日志。
4. 若使用本Skill的API脚本`amap_lookup.py`，读取`AMAP_KEY`/`AMAP_API_KEY`，或用户目录`~/.amap/config.json`的`key`字段。这是脚本约定，与官方MCP配置位置不同。Key私有输入，不写网页或安装包。两种方式选可用的一种，不要求都配置。
5. 用当前行程的一次地点查询验证；再查询实际相邻地点的路线，检查返回状态和坐标系。配置成功不等于路线已查。没有Key且用户暂不配置，可尝试可用地图网页，没查到则保留未知与导航入口。

提示示例：“酒店到橘子洲这一段需要查地铁和打车时间，目前没有可用的高德连接。我已打开高德官方申请教程，请按步骤创建Web服务Key；密钥在本机配置，不用发给我。期间我先继续整理餐厅和景点资料。”必须先检查当前工具，不凭假设发送此提示。

## 中断恢复与验收

保留渠道、待查询条件、停在哪一步、最后核验时间。用户稍后回来只验证缺失步骤；行程日期已变就更新查询条件，不能接着查旧日期。等待期间继续不依赖该渠道的工作。

验收至少覆盖：全新环境；工具齐全无需安装；扩展已装但未启用；错误Chrome个人资料；仅一个网站登录；FlyAI Skill已装但CLI缺失；Key存在但无权限；无Key体验价掩码；用户稍后配置；风险限制不得自动重试。记录真实结果，不能把这份检查表当作已实测。

依据：OpenCLI官方README https://github.com/jackwener/opencli （2026-09-23核对扩展、doctor及个人资料说明）；FlyAI官方Skill与 https://open.fly.ai/ 。版本可能变化，安装前读取当前说明。

## 缺配置时的取舍顺序

确实需要该渠道时：检查当前能力 → 说明缺失项并请用户接力 → 等待期间做其他独立工作。只有用户明确暂不配置/不使用，或出现平台风险限制，才记录原因并转替代来源；不以赶快出网页为由省略提醒。已有充分证据、任务不需要该平台时无需额外安装。配置检查不能只看某个固定路径是否存在，必须核对当前Agent实际可用工具。
