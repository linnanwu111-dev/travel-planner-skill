# 地点配图：公开网页搜索优先

默认从公开网站搜索城市封面和已选地点实景图，不把小红书作为图片素材采集通道。小红书未登录或受限不得阻塞普通网页配图，也不能直接略过搜索后交付全空图片页。

## 时机与步骤

1. 行程地点基本确认后，按稳定place_id去重列出配图清单：城市封面、主要景点、已选酒店/餐厅。相同酒店多天复用一张图，不重复检索。未选中的候选不必提前逐一找图。
2. 复用用户自有且已允许使用的照片；不足时用当前可用网页/图片搜索工具搜索“城市+准确地点名+实景/全景”，酒店餐厅加分店。优先景区或商家官网查真实性，优先明确可复用图库或公共授权图片解决使用许可。官网公开展示不等于自动允许转载。
3. 打开原始来源页，核对拍摄对象、地点、作者、图片使用条件及原图地址；看图确认内容，不把搜索摘要、缩略图或同名异地照片直接当素材。明确可用后才获取素材或使用允许的外链，不绕过访问限制。
4. 顶部城市封面与下面地点卡分开选图：
   - 城市封面选广为人知、能体现当地旅游特色的地标或全景，优先能在横向裁切后保留主体的照片。杭州优先西湖的湖面与代表性景观，长沙优先橘子洲头或五一广场。不能仅因某张图属于该城市或方便取得，就用集贤亭等局部小景充当城市名片；除非用户明确指定。记录选中的主体和选择理由，并看图核对。
   - 每个主行程卡使用该地点的实景：写灵隐寺就用灵隐寺，不用泛西湖图；酒店使用已选酒店准确分店的外观、大堂或实际房型照片；餐厅使用准确分店的门头、店内或可核实属于该店的菜品照片。不能用连锁品牌其他分店或别家照片替代。
   - 酒店先检查 FlyAI 已返回结果是否包含可用图片和来源；有就核对并复用，没有图片字段或无法确认分店就转公开网页、酒店官网等搜索，不猜测图片 URL，也不假称 FlyAI 一定返回图片。餐厅同样可从公开网页及已有商家资料中取得。
   - 每个已选地点都进入配图检查；找不到准确且可用的素材可留空，但必须记录搜索结果并告知用户，不能为凑齐图片放错图。不新增拍照灵感任务。
5. 将图片写入media，关联source_ids、place_id，记录credit及来源许可依据。许可不明用reference_only，不能为了让导出通过伪造permitted。城市封面role=cover，地点图role=place。
6. 页面映射必须检查：`role=cover` 覆盖标题到行程总览底部的整个主题框，采用轻微模糊与浅色遮罩；`role=place` 按 `place_id` 作为对应活动卡片的淡化背景，右上角“查看大图”打开清晰原图。不要把图片重新排成占位侧栏，也不要只填封面漏掉主要景点。更换候选地点时使用新地点的图片；没有新图就留空，不能继续显示旧地点照片。
7. 本地图片放工作包目录内并用相对path；render.py复制到输出。外链须验证可访问。生成后实际打开页面，看背景与大图是否加载、是否对应地点；代码里有URL不算图片已交付。

## 覆盖检查

在私有研究记录中逐项记录：已找到可用素材 / 已搜索但无合适许可或地点不符 / 网络或工具受阻 / 用户不需要。包括搜索关键词、来源与核验结果，不记录登录凭证。

默认应实际搜索城市封面及每个已选景点、酒店、餐厅；用户已有足够可用图片时可复用并说明。不因缺一张照片中止全程规划。搜索后确实无可用图则保留纯色卡，在交付对话简短说明哪些地点缺图及原因；不默默跳过整个图片阶段，不让用户误以为已经配齐。找不到图片不自动改用小红书批量补图。

本文件定义Agent执行步骤，未实现独立自动图片爬虫，也不保证搜索结果一定可使用。

## 搜索受阻时的降级

- robots 拒绝、登录要求、搜索无结果是不同情况：记录实际工具、URL、关键词和返回，不能由一次失败推断整个站点都不可用。已有搜索结果能打开原始素材页时可继续核验；不能只有摘要就认定许可。
- 一个来源受阻后换另一可访问来源，不反复刷新、循环试同站搜索页或绕过限制。每个地点默认尝试两个独立来源；仍无准确且许可明确的图片就停止本轮查找，写入 `research-log.json.image_exceptions` 的 reason 与 evidence_path，保留纯色卡并在交付时说明。用户补图后可继续。
- Pixabay、Unsplash、Pexels、Wikimedia 是候选来源，不是许可证标签。必须核对具体素材及适用条款；“免费商用图库”这个站点描述不能代替图片核验。FlyAI 返回 mainPic、官网可下载、搜索可见或添加署名，也都不自动构成网页再发布许可。
- 不把其他城市或其他分店的图库图凑成地点实景；不用生成图冒充景点实拍。缺图不会阻塞地图、预算和行程交付，不能把找图变成无限循环。

## permitted 的证据结构

非演示行程的每张 `permitted` 图片除 credit、source_ids 和素材路径外，还必须有私有 permission 记录，例如：

```json
{"permission":{"basis":"license","scope":"web_delivery","terms":"记录实际核验的许可名称、适用范围、署名及其他条件；这里不能照抄为许可结论","evidence_path":"evidence/image-license.txt"}}
```

basis 仅选 `license`（适用许可）、`owner_authorization`（权利人授权）或 `user_owned`（用户确认自有且授权本次网页使用）。证据文件保存原始许可/授权摘录、来源 URL（用户授权则记录会话依据）、核验日期，以及与具体图片的对应关系。scope=web_delivery 表示已核验包含本次网页交付；只允许私下查看的图片不能这样标注。记录使用条件并履行署名等要求，不要只写“公开图片，已注明来源”。

许可未知时保留 `reference_only` 或 `unknown`，配合缺图记录正常交付，不要为通过校验捏造许可文件。旧数据包缺少许可依据时先补核验，不能自动批量升级。证据记录不进入公开网页数据包；页面保留必要署名。校验只检查字段和证据文件存在，不能证明授权真实，Agent 仍须阅读核对。
