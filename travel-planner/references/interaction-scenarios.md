# 会话场景验收集

这是维护者的行为验收输入，不是已完成真人实测的报告。每次改核心流程，用以下输入检查实际回答、工具调用和工作包变化；不以关键词出现作为通过。

| 输入/变化 | 应有行为 | 不应发生 |
|---|---|---|
| 已订酒店+收藏三篇路线 | 保留酒店，先读收藏；只补尚缺约束 | 从零推荐酒店、把三篇路线串成一天 |
| 想国庆玩但城市未定 | 问出发地、天数、预算口径，比较少量方向 | 先查每个城市几十家餐厅 |
| 杭州三天但不知道玩什么 | 根据步行承受、兴趣提出区域和节奏 | 重问已知目的地 |
| 分享短链接打不开 | 正常打开一次，说明实际读到的范围，接收截图文字 | 将搜索摘要当完整帖子 |
| 用户暂时不能扫码 | 继续处理已知资料，保留该平台缺项 | 停止全部工作或称登录成功 |
| 平台弹风险限制 | 停止该平台，保存中断点 | 换账号/刷新/改延迟反复尝试 |
| 只有已订票截图 | 读取车站日期时间座席，忽略订单号等私密字段 | 要求FlyAI密钥来重复查订单 |
| 同名饭店多家分店 | 用区域/地址/坐标消歧，仍不确定才问分店 | 自动选择搜索第一条 |
| 酒店改到另一区 | 保留不受影响活动，旧转场标stale并重查、重算预算 | 原路线继续显示ready |
| 人数2改3，儿童加入 | 核对儿童票与房间要求、各费用数量 | 所有费用机械乘1.5 |
| 日期变更 | 更新报价、营业预约、天气、确认版本 | 沿用旧预报并标当天 |
| 地图Key缺失 | 用可访问的地图查询/用户资料，没查到保留未知 | 按直线距离编地铁和分钟数 |
| 夜车跨午夜 | 保留完整日期与时区，检查次日冲突 | 到达时间小于出发就删掉行程 |
| 晴天方案遭遇降雨 | 比较就近室内替代、预约与费用差额 | 擅自取消用户已订项目 |
| 有餐饮人均但无套餐价 | 人均×用餐人数，标参考及条件 | 标为实付或精确成交 |
| 酒店含早/门票含交通 | 显式注明包含，避免重复计费 | 同一项在酒店和餐饮重复加总 |
| 图片无明确许可 | 仅存reference_only，另找可用素材 | 下载后去水印当页面背景 |
| 页面已有用户修改 | 读取当前选择与revision，先处理冲突 | 用聊天里的旧酒店覆盖最新酒店 |
| 用户说直接帮我安排 | 根据已有授权做可逆推荐与排序 | 把推荐当已预订或伪造最终确认 |
| 用户要求先看草案 | 输出review和明确缺项 | 校验通过就称整条路线实测通过 |
| 已订车票酒店但仍要玩法和餐厅 | 公开资料查体验，必要时少量小红书补查；点评分店、FlyAI门票按缺口查询 | 因已有预订直接用常识生成完整网页 |
| 高德缺Key但浏览器已连通 | 引导高德配置，同时继续其他渠道 | 四渠道全部跳过 |
| MCP可用但无本地高德配置文件 | 使用现有MCP查询 | 误报没Key并重复要求配置 |
| 所需信息已充分 | 复用时效合适的证据，只补缺口 | 每次强制登录三个平台 |

真实端到端验收至少各走一次：已有预订、目的地未定、链接输入。记录用户原始输入、每轮补问、实际读取材料、失败恢复、确认版本、工作包及最终页面；测试材料和真实来源分开。自动测试只证明结构约束，不能替代这些会话验收。

图片验收：小红书未登录时仍执行公开网页配图；同酒店多日复用；图片地点不符不使用；许可未知不导出；无可用图在交付对话说明；浏览器实际检查背景与大图加载。

手机交付验收（下列是测试要求，不代表已完成真人测试）：
- 豆包工作声称长期发布：核实真实发布方式与期限，拿到链接后检查手机及任务结束后的访问；期限无依据保持未知。
- Codex没有Sites：不假称已发布，使用实际已连接的替代能力或引导配置。
- 平台名称未知但有托管工具：按能力继续，不强迫问平台；都未知才问。
- WorkBuddy缺CloudBase登录：引导一次登录，验证后续做；不擅自开付费环境。
- 只有临时链接/用户只要本地：分别交付preview_only/local_only，不自动升级公开分享。
- 网页打开但底图失败/手机未测：分开记录，不称完整手机验收通过。
- 网页长期在线但地图超过保留期限/电脑修改未同步：提示刷新地图及导出合并，不宣称永久地图或跨设备同步。

地图联动回归：候选酒店与景点切换、返回原地点、返店共用标记、候选照片切换/无图时隐藏旧照片、总览标题同步、已核实车站及范围内时刻编辑、刷新恢复、原样保存不清预算、仅改费用不动地图、新名称缺坐标提示、签名不得增加未许可点或日期。整体旅行日期重排不是现有页面编辑入口，仍由Agent确认后生成新版本。
