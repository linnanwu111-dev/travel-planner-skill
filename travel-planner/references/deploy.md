# 手机交付与平台适配

在当前C版生成、资料缺项说明和本地检查之后进入本环节。用户要求手机打开、分享或发布时，继续完成部署；尚未表达意愿时简短提供手机发布选项，不擅自把私人行程公开。用户只要本地文件时到此停止。不要为发布重新设计页面。

## 1. 识别环境与可用能力

先读取当前会话明确的平台信息、已提供的工具/连接器和已安装发布Skill；只检查与发布有关的配置，不扫描用户无关目录或输出凭证。记录平台名称及判断依据，再检查实际发布工具是否可调用、账号是否连接、是否有可复用的目标项目。平台身份与发布能力分开判断：出现Sites工具可证明有该能力，不单独证明正在Codex；模型名称、路径名、网页标题或Agent自述都不能单独证明平台身份。

如果平台不确定但有可用托管工具，按能力继续；若平台和能力都不明，问一句“你现在使用的是哪个Agent，有没有发布网站的入口？”不要要求用户了解技术栈。没有通用命令可以可靠识别所有Agent，不能编造环境检测结果。

## 2. 选择平台路径并引导

用户指定的平台优先；否则用当前已连接、适合完整静态网站的正式托管能力。以下是选择方向，实际操作必须读取当前平台自己的工具说明、发布Skill或官方文档，不能照猜测执行命令。

| 环境 | 优先路径 | 必须核实 |
|---|---|---|
| 豆包工作 | 检查云电脑/工作区实际提供的网站发布或托管功能，按其引导发布完整攻略目录 | 是否仅转发临时进程端口、链接有效期、休眠/结束任务后是否可访问、是否要求访客登录。尚无已核验的长期托管保证，不能只复述“可以永久部署” |
| Codex / ChatGPT 且Sites可用 | 读取当前Sites发布Skill，通过Sites正式部署现有静态产物 | 账号权限、访问范围、额度与限制。无Sites时查现有连接器或推荐其他静态托管，不宣称所有账号自带 |
| WorkBuddy | 检查内置CloudBase连接器或当前官方推荐的正式发布能力，按自身引导操作 | 环境/账号是否开通，连接及部署返回。无需自建虚拟机不等于无需云托管账号 |
| 其他Agent | 查实际工具、安装的部署Skill及该平台官方说明，推荐一种最合适的静态托管路径 | 优先已有连接、国内手机可达、正式HTTPS链接；没有能力时再引导接入，不能虚构发布工具 |

平台特性会变化，执行时复核。参考入口：
- ChatGPT Sites：https://help.openai.com/en/articles/20001339-creating-and-managing-chatgpt-sites
- WorkBuddy CloudBase：https://docs.cloudbase.net/ai/cloudbase-ai-toolkit/ide-setup/workbuddy
- 腾讯部署方式说明：https://www.codebuddy.ai/docs/zh/ide/User-guide/deploy （这是CodeBuddy说明，不能当作WorkBuddy已有同样工具的证明；Cloud Studio临时预览与正式托管要区分。）

缺少登录/连接时，只引导当前需要的一步，让用户扫码或授权后检查实际连接并续做，不先要求注册一串服务。费用、公开范围或新账号等必要选择须说明具体影响；已有明确授权不要重复询问。不要未经用户选择替其开通付费资源。平台不支持或部署失败时记录真实原因，提出一个可行接力方式；保留网页文件包，不把失败说成上线成功。

## 3. 发布完整产物

上传render.py的当前输出目录及其相对路径素材，不能只上传index.html。检查导出的HTML、JSON、图片是否包含用户不希望公开的内容，按已确认的分享范围配置；私有plan.json、research-log、原始订单/截图、service.json及任何查询/上游凭证不进入发布目录。不要上传整个项目或Skill安装目录。

Agent在规划阶段调用我们的托管查询服务；最终页面只展示整理后的数据和签名地图图片，无需把服务token写进浏览器。用户平台托管攻略、我们的服务器提供查询与地图，两者独立；当前查询服务器不是默认的用户网页上传服务，不能虚构上传接口。相对图片路径、JS和CSS应保持不变，托管在子路径时检查资源解析。

复用已有站点时先读取平台当前状态和用户网页修改，遵循平台版本发布流程，不另建重复站点。记录实际返回的站点ID/URL，后续更新复用；保留源文件便于迁移。不要把本机127.0.0.1、file://、二维码图片路径或临时隧道当正式公网链接。

## 平台只预览单个 HTML 时

交付前区分完整目录托管与单文件附件预览。不能把本地 serve.py 验收记录沿用到平台链接；也不能假设平台会自动上传 HTML 引用的 assets/、media/。先核实当前预览机制，再选择产物。

如果当前平台只能托管单个 HTML，可在保留原目录版的同时制作 index-standalone.html：内联本地 CSS、JS、素材和图标，检查 CSS url()、JS 动态资源路径及依赖顺序，不只替换 HTML 中的 src。保持当前 C 版功能和数据；不重新设计。查询凭证不能内联，签名地图仍需联网。当前 Skill 未内置单文件打包器，需要执行 Agent 按实际产物完成转换并验证，不能声称 render.py 已自动生成此版本。

核实平台的文件大小及脚本限制，超限或禁止脚本时改用完整静态站点托管；不要反复交付失效的单文件预览。单文件化不等于离线地图、长期托管或跨设备同步。不得擅自压缩到地点照片无法辨识。

## 4. 验收与持久性

按平台允许的验证方式检查部署成功和实际URL。若平台发布Skill禁止自动抓取线上站点，遵循它的流程，手机实际访问交给用户；不能把平台部署状态当作手机实测。

交付入口改变后必须重新验收实际入口：本地目录 → 平台预览 → 正式站点分别记录 URL、产物版本、检查时间和结果。资源打包或内联后也要重测，不能仅因同一份数据而沿用旧结果。

在平台允许时实际打开将发给用户的链接，检查 CSS/JS/图片是否成功加载、返回内容类型是否正确、Console 是否报错，确认动态行程已显示。再操作切日、费用编辑并保存刷新、清单勾选并刷新、导航弹层；“按钮存在”不算交互通过。无法访问该入口或不能操作时明确待验，不宣称“全部实测通过”。允许公开访问的站点尽量用非作者会话验证，排除只有工作区内可用的资源地址。

检查以下结果，未测项明确写待验：
- 手机尺寸布局、中文文字、本地图片与背景、切换日期、费用与清单、折叠通勤可用。
- HTTPS底图真实加载，当日/全部总览正常；地点导航目标正确。网站能打开不等于地图可用，App唤起另需真机确认。
- 目标访客的权限符合选择：公开分享可用未登录浏览器测试；私有分享用授权账号，不为省登录擅自改公开。
- 国内手机关闭VPN、使用移动网络打开实际链接。桌面浏览器模拟手机只能证明布局，不能冒称手机移动网络通过。
- 核实发布方式、已知有效期、休眠依赖与费用条件。若平台是云电脑端口预览，用户方便时关闭任务/云电脑后重开链接测试；不要擅自停止其工作区。没有长期承诺来源时标“已发布，有效期待确认”，一次成功不能证明永久可用。

当前新生成地图签名有效至返程后第90天结束，即使网页长期托管也需到期前返回Agent重新生成并发布地图数据。出行跨过过期日时提前说明刷新安排，不称网页所有功能永久有效。当前费用/清单修改存在浏览器本地，不自动在电脑手机间同步；需要迁移时导出调整交回Agent合并，不暗示发布就获得云同步。

## CloudBase 接力部署

当前平台没有合适的正式托管能力时，可将 CloudBase 作为静态网页托管备选，优先复用用户已有账号与环境。不能只推荐名称或给文档链接就结束：由当前 Agent 继续检查已安装的 CloudBase Skill/连接器，读取相关部署指南；未安装时按当前工具支持的安装流程引导接入，不猜测命令或自动开通收费资源。

用户选择该方式后，由当前 Agent 持续接管后续流程：引导登录或授权 → 检查可用环境及静态托管能力 → 说明必要的访问范围与费用选择 → 发布完整网页目录 → 获取实际 HTTPS 地址 → 按本文件验收并交付手机链接。登录、扫码和必要授权需要用户完成时，只停在该步骤，完成后继续；无调用能力时提供当前官方方式的逐步操作，并核验用户返回的部署结果，不虚构已部署。不得上传原始研究包、密钥或账号配置文件。

## 5. 手机交付回复与记录

给用户实际HTTPS链接；工具可用时为同一已验证链接生成二维码（不要用图像生成模型绘制二维码），无二维码工具不阻塞链接交付。简短说明访问是否需登录、链接期限/未知条件、地图到期刷新、手机验收状态、后续更新方法；保留完整文件包作为备份。

私有工作目录写deployment-record.json，至少包含：platform及识别依据、provider、site_id（如有）、trip_id/revision、发布目录、实际url、audience、deployed_at、已知expires_at或null及依据、地图最早expires_at、检查结果、待用户动作。状态区分local_only / preview_only / deployed / blocked；手机验收单独记录passed / pending / failed，不能用deployed代替。记录无token、Cookie或上游Key。

参考自然交付：“攻略已发布：[链接]。手机可以从这里打开；实际移动网络访问还请你试一下。地图有效至×月×日，届时回到对话刷新；修改清单目前只保存在当前手机浏览器。”只填写实际确认的信息。

## 当前版本默认使用方式：手机继续编辑

与Agent讨论确认后，将行程、车票、酒店、景点、预算等基础结构化数据随完整C版产物发布；手机首次打开直接加载这些内容，不依赖电脑的localStorage。地图通过随包签名链接联网加载，本地图片随目录发布。不要让用户重新输入基础行程。电脑浏览器里尚未回填的修改不会自动发布，发布前若有此类调整先导出并合并。

最终回复主动说明：“确认好的行程、车票、酒店和基础预算已经放进网页，手机打开就能看到。接下来建议固定用手机上的同一个浏览器打开，勾选清单和调整费用会保存在该浏览器。换浏览器、清除网站数据或使用无痕模式可能无法保留；重要调整可以导出备份。”不要求用户为此配置云同步。

手机端编辑仍遵守现有功能边界：勾选和费用调整可本地保存；切换已核实候选酒店/景点、行程范围内已核实车站后，网页自动更新地图坐标与顺序连线（需新版签名地图及网络）；相邻通勤耗时和费用仍标待核。新名称缺坐标、整体出游日期变化等需导出交回Agent重查，不把重画连线当成交通报价已更新。重新发布前保留手机调整，按trip_id/revision合并，避免丢失。
